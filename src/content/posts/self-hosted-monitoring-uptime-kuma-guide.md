博客能访问不代表稳定可用。真正的运维能力，是问题出现时你能第一时间感知并定位。
这篇文章用 Uptime Kuma 做一个低成本监控系统，适合个人站和小服务。

## 1. 为什么选 Uptime Kuma

- 部署简单：Docker 一条命令即可起
- 可视化强：状态页清晰，适合快速巡检
- 通知丰富：支持 Telegram、Webhook、邮件等

## 2. Docker 部署

```bash
docker run -d \
  --restart=always \
  -p 3001:3001 \
  -v uptime-kuma:/app/data \
  --name uptime-kuma \
  louislam/uptime-kuma:1
```

访问 `http://server-ip:3001` 初始化管理员账户。

## 3. 监控项设计

建议至少配置 4 类：

1. 首页 HTTP 状态（200/301）
2. 关键页面响应时间（如归档页、搜索页）
3. SSL 证书剩余天数
4. DNS 解析健康度（可选）

轮询间隔不必太短，个人站通常 1-5 分钟足够。

## 4. 告警策略

告警不是越多越好，关键是“可执行”。

建议：

- 连续 2-3 次失败再告警，减少抖动误报
- 恢复通知开启，便于确认故障结束
- 夜间低优先级告警可降频

## 5. 公共状态页

如果你的博客面向用户，可开启状态页：

- 展示历史可用性
- 提供故障透明度
- 减少读者反复询问“是不是我网络问题”

## 6. 常见故障排查

1. 监控显示超时，但站点可访问：可能是服务器到探测节点路径异常。
2. SSL 提前告警：检查证书链是否完整。
3. 偶发 502：先看反向代理和上游服务重启记录。

## 总结

监控是个人站稳定运营的分水岭。
当你能提前知道故障并快速响应，站点质量和读者信任都会明显提升。
