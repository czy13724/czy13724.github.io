## 前言：为什么需要自动化转换？

随着代理工具的多样化，用户群体分散在 Quantumult X, Surge, Stash, Loon 和 Shadowrocket 等不同平台上。作为脚本开发者，维护单一格式（通常是 Qx 格式）最轻松，但为了覆盖更多用户，通过手动复制粘贴来适配不同平台的格式既低效又容易出错。

本文将介绍一套基于 **GitHub Actions** 的全自动化解决方案。你只需要维护一份 Quantumult X 格式的脚本，Push 到仓库后，转换脚本会自动将其生成为其他所有主流平台支持的格式，并同步更新，真正实现“一次编写，到处运行”。

## 核心功能

*   **全平台兼容**：自动将 Qx 的 `js`、`conf`、`snippet` 格式转换为 `sgmodule` (Surge), `plugin` (Loon), `stoverride` (Stash) 等文件。
*   **智能注入**：在源文件中自动注入转换后的跨平台链接注释，方便用户直接通过原始链接跳转或订阅。
*   **零感触发**：自动监听存放脚本文件夹的变动。你只需要提交代码，剩下的交给 GitHub Actions。
*   **兼容性**：支持自动创建缺失的目录结构。

**如何测试？**
尝试修改或添加一个 `.js` 脚本文件并 Push 到仓库。观察 GitHub Actions 页面，检查工作流是否成功运行。
*   **成功**：你会看到转换后的文件自动出现在对应的文件夹中。
*   **失败**：点击 Fail 的日志查看详情。如果是“文件内容匹配错误”，通常意味着你的 Qx 脚本头部注释格式不符合标准，请参考下文的模版规范。

## 开发者规范

为了确保转换脚本能准确识别元数据，请遵循以下注释规范。

### 脚本头部模版
⚠️ <span style="color:red;">**关键要求**：脚本内容中必须包含 **[rewrite_local]**、**[mitm]**（或 [MITM]）以及 **hostname** 字段系统才能识别并转换。</span>

```javascript
/*
项目名称：示例项目 Demo
使用说明：这是一个演示脚本。
更新时间：2024-02-07
*/

[rewrite_local]
# 匹配模式一：响应体修改
^https:\/\/api\.example\.com\/v1\/user\/profile url script-response-body https://raw.githubusercontent.com/user/repo/main/scripts/demo1.js

# 匹配模式二：请求头修改
^https:\/\/shop\.example\.com\/api\/list url script-request-header https://raw.githubusercontent.com/user/repo/main/scripts/demo2.js

[mitm]
hostname = api.example.com, shop.example.com

[task_local]
# 定时任务（可选）
1 */6 * * * https://raw.githubusercontent.com/user/repo/main/scripts/demo.js, tag=示例任务, img-url=https://example.com/icon.png, enabled=true
```
