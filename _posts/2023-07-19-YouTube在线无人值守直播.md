## 第一阶段：服务器准备与环境配置

要在无人值守的情况下进行 24/7 直播，你需要一台 **上行带宽充足** 且 **流量充裕** 的 VPS。
*   **配置建议**：CPU 1核以上，内存 1GB 以上。
*   **流量警告**：720p 推流每小时消耗约 1GB 流量，一个月需要 720GB+。请确保你的 VPS 流量足够或为无限流量。

### 1. 安装 FFmpeg

FFmpeg 是处理多媒体内容的神器。

**Ubuntu / Debian:**
```bash
apt update
apt install -y ffmpeg
```

**CentOS / AlmaLinux:**
```bash
yum install -y epel-release
rpm -v --import http://li.nux.ro/download/nux/RPM-GPG-KEY-nux.ro
rpm -Uvh http://li.nux.ro/download/nux/dextop/el7/x86_64/nux-dextop-release-0-5.el7.nux.noarch.rpm
yum install -y ffmpeg ffmpeg-devel
```

**验证安装:**
```bash
ffmpeg -version
```

### 2. 准备视频素材

在服务器上创建一个目录存放视频文件：
```bash
mkdir -p /root/video
```
使用 FTP 工具（如 FileZilla）或 `scp` 命令将你的 MP4 视频文件上传到该目录下。
*   **注意**：为了保证直播稳定性，建议提前将视频转码为 H.264 编码 + AAC 音频格式，尽量避免直播时进行实时转码（非常消耗 CPU）。

## 第二阶段：构建推流命令

我们不使用不透明的一键脚本，而是直接构建 FFmpeg 命令，这样你才能理解每一部分的含义并进行自定义。

### 获取推流码
登录 [YouTube Studio](https://studio.youtube.com/)，点击右上角“创建” -> “开始直播”。在直播后台复制 **推流网址 (RTMP URL)** 和 **直播码 (Stream Key)**。

### 核心命令解析

一个标准的循环推流命令如下：

```bash
ffmpeg -re -stream_loop -1 -i "/root/video/video.mp4" \
-c:v copy -c:a aac -b:a 192k \
-f flv "rtmp://a.rtmp.youtube.com/live2/你的直播码"
```

*   `-re`: 按原视频帧率读取（Real-time）。如果不加这个，FFmpeg 会以最快速度读取文件，导致直播流瞬间结束或缓冲区溢出。
*   `-stream_loop -1`: 无限循环读取输入文件。
*   `-i "..."`: 输入文件路径。
*   `-c:v copy`: **关键参数**。直接复制视频流，不进行重新编码。这也意味着你的 VPS CPU 占用率会极低。
*   `-c:a aac`: 音频编码为 AAC（YouTube 标准）。
*   `-f flv`: 输出格式为 FLV（RTMP 协议要求）。

## 第三阶段：使用 Systemd 实现后台保活 (推荐)

传统的 `screen` 方法在服务器重启后会失效，且进程挂掉后不会重启。我们可以创建一个 Systemd 服务，从根本上解决“掉线”问题。

### 1. 创建服务文件

使用编辑器新建文件：
```bash
nano /etc/systemd/system/youtube-stream.service
```

粘贴以下内容（**请修改 `ExecStart` 中的文件名和推流码**）：

```ini
[Unit]
Description=YouTube 24/7 Livestream Service
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root
# 遇到错误自动重启，间隔 10 秒
Restart=always
RestartSec=10

# 核心推流命令 (请替换 video.mp4 和 直播码)
ExecStart=/usr/bin/ffmpeg -re -stream_loop -1 -i /root/video/video.mp4 -c:v copy -c:a aac -b:a 192k -f flv rtmp://a.rtmp.youtube.com/live2/你的直播码

[Install]
WantedBy=multi-user.target
```

按 `Ctrl+O` 保存，`Ctrl+X` 退出。

### 2. 启动并设置开机自启

```bash
# 重载配置
systemctl daemon-reload

# 启动服务
systemctl start youtube-stream

# 设置开机自启
systemctl enable youtube-stream
```

### 3. 管理直播状态

*   **查看状态**（查看是否有报错）：
    ```bash
    systemctl status youtube-stream
    ```
*   **停止直播**：
    ```bash
    systemctl stop youtube-stream
    ```
*   **重启直播**：
    ```bash
    systemctl restart youtube-stream
    ```

## 进阶技巧：多文件轮播

如果你有一堆视频想要随机或顺序播放，而不是单曲循环，可以使用 `concat` 协议。

1.  创建一个列表文件 `playlist.txt`：
    ```text
    file '/root/video/song1.mp4'
    file '/root/video/song2.mp4'
    file '/root/video/song3.mp4'
    ```

2.  修改推流命令：
    ```bash
    ffmpeg -re -f concat -safe 0 -stream_loop -1 -i playlist.txt \
    -c:v copy -c:a aac -b:a 192k \
    -f flv "rtmp://..."
    ```

## 常见问题 (FAQ)

**Q: 为什么直播很卡顿？**
A:
1.  **上传带宽不足**：检查 VPS 的上行带宽。
2.  **TCP 堵塞**：国际网络连接 YouTube 服务器可能丢包。建议开启 BBR 加速。
3.  **码率过高**：如果你的视频是 4K 或高码率 1080p，尝试转码为低码率版本。

**Q: 报错 `Stream ends prematurely`？**
A: 你的输入视频文件可能损坏，或者 FFmpeg 读取速度跟不上推送速度。尝试去除 `-re` 参数（仅在转码模式下），或者检查文件完整性。

**Q: 版权警告？**
A: YouTube 的 Content ID 系统非常强大。如果你播放受版权保护的音乐或电影，直播间会很快被封禁。请务必使用 **无版权 (No Copyright / Royalty Free)** 的素材。
